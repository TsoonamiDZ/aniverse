# Aniverse · موقع أنمي احترافي

موقع أنمي عربي (RTL) كامل المزايا: سلايدر سينمائي، بطاقات بتقييمات، صفحات تفاصيل
بالقصة العربية (من ويكيبيديا العربية)، مشغّل فيديو متعدد المزوّدين والجودات، وبحث حي.

**قاعدة البيانات مضمنة بالكامل** (2,187 أنمي · 25,866 حلقة · 149,244 رابط مشاهدة)
مستخرجة من okanime.xyz، ومُثراة ببيانات AniList/MyAnimeList + ويكيبيديا العربية.

## التشغيل على حاسوبك

### المتطلّبات
- [Bun](https://bun.sh) (وقت تشغيل JavaScript) — أو Node.js 20+

### الخطوات
```bash
# 1. فك ضغط الحزمة
unzip aniverse-site.zip
cd aniverse-site

# 2. تثبيت الاعتمادات
bun install   # أو: npm install

# 3. (اختياري) مزامنة قاعدة البيانات مع مخطط Prisma
bun run db:push

# 4. تشغيل الموقع
bun run dev
```

افتح **http://localhost:3000** في متصفّحك.

## المزايا

- **الصفحة الرئيسية**: سلايدر سينمائي بخلفية بانر عريضة، تقييمات ★/10، تصنيفات،
  بطاقات احترافية، بحث حي، فرز (الأكثر رواجاً / الأعلى تقييماً / الأكثر حلقات /
  أبجدي / اكتشاف).
- **صفحة الأنمي**: قصة عربية (من ويكيبيديا)، تصنيفات عربية، استوديو، حالة، سنة،
  مدة، روابط MAL وAniList، زر الإعلان (trailer)، وقائمة حلقات.
- **صفحة المشاهدة**: مشغّل iframe + مُحدِّد مزوّدين وجودات (FHD/HD/SD) + تنقّل
  بين الحلقات + قائمة جانبية.
- **مبدّل ثيم** داكن/فاتح.

## أداة التحديث (واجهة إدارية منفصلة ومحمية)

الأداة **منفصلة عن الموقع العام** على المسار **`/admin`** — لا يصل إليها الزوّار
العاديون. محمية بكلمة سر (اضبطها عبر متغيّر البيئة `ADMIN_PASSWORD` في `.env`؛
القيمة الافتراضية `aniqa-admin` — **غيّرها قبل النشر**).

### كيف تستخدمها
1. افتح **`/admin`** في المتصفّح → أدخل كلمة السر.
2. اضغط **«فحص الجديد»** → تفتح الأداة خرائط okanime وتعرض لك **قائمة** بالأنميات
   والحلقات الجديدة (بوسترات + أرقام حلقات + عدد روابط المشاهدة) في واجهة رسومية.
3. راجع القائمة، ثم اضغط **«تحديث قاعدة البيانات»** → تُدرج الأداة الجديد فعلاً.
4. ارجع إلى الموقع العام → سترى الأنميات/الحلقات الجديدة ظاهرة.

> الأداة idempotent وقابلة للاستئناف — إعادة الفحص آمنة ولا تكرّر الإدراج.

### تشغيل الأداة من الطرفية (اختياري)
```bash
bun run scripts/sync-okanime.ts                 # مزامنة كاملة (فحص + إدراج)
bun run scripts/sync-okanime.ts --dry-run       # فحص فقط بدون كتابة
bun run scripts/sync-okanime.ts --limit 50     # أول 50 حلقة جديدة
bun run scripts/sync-okanime.ts --since 2026-10-01
```

## النشر على استضافة

### ⚠️ ملاحظة مهمة حول Vercel
Vercel خادم **serverless** بنظام ملفات مؤقت — لذا قاعدة SQLite (ملف) **لا تدوم** فيه
(القراءة تعمل لأن الملف مُحزَّم، لكن الكتابة مثل إضافة أنمي جديد عبر أداة التحديث
تُمحى مع كل استدعاء بارد). **لكي تبقى الأنميات الجديدة، استخدم Turso** (قاعدة
libSQL بعيدة متوافقة مع SQLite، مجانية، تعمل على serverless).

### النشر على Vercel + Turso (موصى به)
1. **أنشئ قاعدة Turso** (مجاناً):
   - أسهل: من لوحة Vercel → **Storage/Integrations → Turso** → Create database.
   - أو من https://turso.tech : أنشئ حساباً، ثم `turso db create aniverse`.
   - احصل على `libsql://...` ورابط **auth token**.
2. **ادفع المخطط إلى Turso** (يُنشئ الجداول):
   ```bash
   DATABASE_URL='libsql://<turso-url>?authToken=<token>' bun run db:push
   ```
3. **انسخ البيانات** من SQLite المحلي إلى Turso:
   ```bash
   bun run scripts/migrate-to-turso.ts 'libsql://<turso-url>?authToken=<token>'
   ```
   (أو مرر التوكن كوسيط ثاني). هذا ينسخ الأنميات والحلقات وروابط المشاهدة.
4. **اضبط متغيرات البيئة على Vercel**:
   - `DATABASE_URL` = `libsql://<turso-url>?authToken=<token>`
   - (اختياري) `ADMIN_PASSWORD` = كلمة سر أداة التحديث.
5. **انشر** على Vercel (`bun run build` ينجح، والموقع يقرأ/يكتب من Turso → الأنميات
   الجديدة تدوم).

> الآن عند استخدام أداة التحديث (`/admin`)، تُكتب الإضافات في Turso (بعيدة)
> فتبقى دائمة عبر كل الاستدعاءات.

### نشر على استضافة دائمة (SQLite يعمل كما هو) — موصى به

على خادم بنظام ملفات **دائم قابل للكتابة**، تعمل SQLite الملفية بدون Turso ولا ترحيل.
المشروع جاهز بـ`Dockerfile` + `start.sh` يبذّر التخزين الدائم تلقائياً.

#### 🟢 Render (أسهل، واجهة رسومية مثل Vercel)
1. ارفع المشروع إلى GitHub (يضمّن `db/custom.db` + `Dockerfile` + `start.sh`).
2. https://render.com → **New → Web Service → اربط مستودع GitHub**.
3. Render يكتشف `Dockerfile` تلقائياً → Build/Run جاهزان.
4. **أضف قرصاً دائماً**: Settings → Disks → Add Disk → اسم `data`، مسار `/data`، حجم 1GB.
5. اضبط متغيرات البيئة: `ADMIN_PASSWORD` = كلمة سر قوية.
6. Deploy → يعمل الموقع + الأنميات الجديدة (عبر `/admin`) تبقى دائمة.

#### 🔵 Fly.io (مجاني بالكامل)
```bash
# ثبّت flyctl من https://fly.io/docs/hands-on/install-flyctl
fly launch            # يقرأ fly.toml + Dockerfile، يُنشئ التطبيق
fly volumes create data --size 1   # التخزين الدائم
fly deploy
# اضبط ADMIN_PASSWORD: fly secrets set ADMIN_PASSWORD=<كلمة-قوية>
```

#### 🟠 Railway / VPS / Render VPS
- **Railway**: اربط المستودع، أضف Volume على `/data`، Start Command = `bash start.sh`.
- **VPS** (Oracle Cloud مجاني دائماً): انسخ المشروع، `bun install && bun run db:push && bun run build && bash start.sh`.

> على أيّها، `start.sh` يتحقق: إن كان القرص الدائم فارغاً، ينسخ قاعدة البيانات المُحزَّمة
> إليه في أول تشغيل. بعدها كل الكتابات (أداة التحديث) تدوم على القرص الدائم.

## سكريبتات إثراء إضافية (اختيارية)

- `scripts/import-catalog.ts` — استيراد فهرس okanime الكامل إلى SQLite (إن بدأت
  من قاعدة فارغة).
- `scripts/enrich-anilist.ts` — إثراء ببيانات AniList/MyAnimeList (تقييم، تصنيفات،
  بانر، إعلان، استوديو...).
- `scripts/enrich-ar-wiki.ts` — إثراء بالقصة العربية من ويكيبيديا العربية.

## البنية التقنية

- **Next.js 16** (App Router) + **TypeScript** + **Tailwind CSS 4** + **shadcn/ui**
- **Prisma ORM** + **SQLite** (ملف `db/custom.db`)
- **TanStack Query** لحالة الخادم، **Zustand** للعميل، **framer-motion** للحركات
- **sonner** للإشعارات، **next-themes** للثيم

ملف فيديو؛ التشغيل عبر مُضمّنات المزوّدين. البيانات الوصفية (تقييم، تصنيفات، قصة
عربية) من AniList/MyAnimeList وويكيبيديا العربية. لأغراض الفهرسة والمعاينة.
